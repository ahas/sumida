# 시스템 설정

> **이 문서를 고치는 사람에게.**
>
> 이 문서는 **정본**이다. 운영 설정이 어디에 살고, 누가 그것을 소유하고, 실행 중인 코드가 그
> 값을 어떻게 읽는지를 여기서 읽을 수 있어야 한다. 여기 적힌 것과 구현이 어긋나면 둘 중 하나가
> 틀린 것이다.
>
> 다음 두 가지는 **적지 않는다.**
>
> 1. **구현 코드 인용 금지.** 러스트 소스, 파일 경로, 줄 번호를 근거로 끌어오지 않는다. 타입·개념·
>    설정 키의 **이름**을 부르는 것은 인용이 아니므로 얼마든지 쓴다. 설정 키 이름은 운영자·클라이언트
>    와의 계약이므로 본문에 그대로 쓴다.
> 2. **수정 이력 금지.** "원래는", "이전 버전에서는" 같은 서술을 남기지 않는다. 이력은 git과
>    CHANGELOG의 일이다. 이 문서는 **지금 무엇이 참인지만** 말한다.
>
> **고칠 때는 덧붙이지 말고 해당 부분을 다시 쓴다.**

---

## 1. 시스템 설정 저장소란 무엇인가

시스템 설정 저장소는 **서비스가 돌아가는 동안 바뀔 수 있는 운영 설정의 key-value 저장소**다.
키는 점으로 구분한 이름이고, 값은 JSON이다. 값 하나는 자기 자신에 대해 다음을 함께 들고 있다.

| 항목 | 뜻 |
|---|---|
| 자료형 | 값이 무엇인지 — string, integer, number, boolean, duration_days, json |
| 범위 | 수치형이 받는 최솟값·최댓값. 없으면 제한이 없다 |
| 라벨·설명 | 사람이 읽을 이름과 부연. 값이 아니라 번역 키를 담는다 |
| 편집 가능 여부 | 운영자가 화면에서 고칠 수 있는 값인지, 서버가 자동으로 관리하는 값인지 |
| 분류 | 이 설정이 어느 갈래에 속하는지 |
| 갱신 정보 | 마지막으로 바꾼 시각과 바꾼 사람 |

자료형과 범위는 장식이 아니다. 값을 갱신할 때 자료형 정합성과 범위를 검사하고, 어긋나면 거부한다.
편집 불가로 표시된 행은 운영자 경로로는 바뀌지 않고, 서버가 스스로 등록·갱신하는 경로로만 바뀐다.

## 2. 어떤 값이 어디에 사는가

값이 살 자리는 세 곳이고, 판정 기준은 **"누가 언제 그것을 바꾸는가"** 하나다.

**설정 파일에 사는 값.** 프로세스가 자기 자신을 세우는 동안 **한 번 읽고 마는 값**, 또는 **비밀**.
연결 문자열, 커넥션 풀 크기, 바인드 주소, 실행 단계, CORS 허용 출처, 세션 저장소 종류와 쿠키 속성,
클라우드 리전과 버킷, API 키, 외부 서비스 주소, 서명 비밀의 보관처가 여기다. 이런 값은 바꾸려면
어차피 프로세스를 다시 세워야 하므로 데이터베이스에 두어도 얻는 것이 없고, 비밀은 애초에 조회
가능한 표에 두지 않는다.

**시스템 설정 저장소에 사는 값.** **운영자가 돌아가는 시스템에서 그것을 바꿀 이유가 있는 값.**
임계치, 재시도 횟수와 backoff, 보관 기간, 유예 시간, 기능 on/off 스위치가 여기다. 판정하는 질문은
"운영 중에 이 숫자를 돌리고 싶어질 사람이 있는가"이고, 답이 예이면 재배포를 요구해서는 안 된다.

**코드 상수로 남는 값.** **정책이 아니라 자료구조를 조율하는 값.** 내부 배치 크기, 채널 용량,
파서 방어 한계, 플러시 주기가 여기다. 이런 값을 돌릴 이유가 있는 사람은 그 코드를 고치는 사람뿐이고,
운영자에게 노출하면 의미를 알 수 없는 손잡이만 늘어난다.

경계에 걸리는 값이 있으면 **설정 파일 쪽으로 기울인다.** 저장소로 옮기는 것은 언제든 할 수 있지만,
운영자가 이미 돌려 본 손잡이를 없애는 것은 그렇지 않다.

## 3. 분류(category)

분류는 설정 자신의 속성이고, 그 설정을 소유한 쪽이 선언한다. 어휘는 다음이 전부다.

| 분류 | 무엇이 여기 오나 |
|---|---|
| `auth` | 인증·접근 통제 정책 — 로그인 실패 잠금, 차단 대상과 기간 |
| `execution` | 일이 실제로 굴러가는 방식 — 재시도 정책, 큐 유예, 종료 유예 |
| `retention` | 무엇을 얼마나 오래 들고 있는가 — 로그·지표 보관 기간, 정리 주기와 한도 |
| `storage` | 데이터가 어디에 놓이는가 — 보관 대상 버킷과 경로 접두사 |
| `general` | 위 어디에도 속하지 않는 값. 아무것도 선언하지 않은 행의 기본값 |

분류는 클라이언트가 설정 화면을 묶는 데 쓴다. 새 갈래가 필요해 보이면 어휘를 늘리기 전에 이 표를
먼저 고친다 — 어휘가 여기 적힌 것이 전부라는 사실이 이 표의 값어치다.

## 4. 누가 어떤 키를 소유하는가

**기반 층은 자기 키만 심고, 그 위에 선 서비스는 자기 키만 심는다.** 어느 쪽도 상대의 키 목록을
알지 않는다.

- 기반 층은 표와 자료형 어휘, 접근 헬퍼, 그리고 **자기 자신이 쓰는 설정**을 소유한다. 인증 정책
  설정(`security.ban.*`)이 그렇다.
- 그 위에 선 서비스는 **자기 마이그레이션에서 자기 키를 시드**하고, 그 키 문자열을 자기 크레이트의
  키 상수 모듈로 소유한다.
- 시드는 **멱등**하다. 키가 이미 있으면 아무것도 하지 않는다. 이미 배포된 데이터베이스에 대해서도,
  마이그레이션을 다시 돌려도 운영자가 고쳐 둔 값을 덮지 않는다.
- 표를 만드는 마이그레이션이 시드 마이그레이션보다 먼저 온다. 그 위에 선 서비스는 자기 Migrator에서
  그 순서를 지킨다.

키 문자열은 코드 곳곳에 흩어진 리터럴이 아니라 **상수**로 산다. 키를 부르는 자리와 키를 심는 자리가
같은 이름을 보게 하는 것이 목적이다.

## 5. 값이 실행 중인 코드에 닿는 방법

값을 읽는 코드는 **저장소에 키를 묻고, 답이 없으면 설정 파일 값을 쓴다.** 다음 세 경우가 모두
"답이 없음"이다.

- 행이 아직 없다 — 시드되지 않은 데이터베이스.
- 행은 있는데 값이 기대한 자료형이 아니다.
- 조회 자체가 실패했다 — 데이터베이스에 문제가 있다.

셋 다 대체값으로 넘어가고, 조회가 실패한 경우에는 warn 수준으로 남긴다. **데이터베이스 문제가
로그인 경로를 끊어서는 안 된다.** 아직 시드되지 않은 데이터베이스를 상대로도 서비스는 뜬다.

대체값은 설정 파일이 들고 있는 같은 이름의 값이고, 설정 파일에도 없으면 그 구조체의 기본값이다.
그래서 한 설정에는 항상 답이 있다 — 저장소 값, 설정 파일 값, 코드 기본값 순으로 처음 잡히는 것.

값은 **쓰이는 시점에 읽는다.** 부팅 때 읽어 캐시해 두면 운영자가 화면에서 고친 값이 프로세스를
다시 세울 때까지 반영되지 않으므로, 저장소에 둔 의미가 사라진다.

## 6. 라벨과 설명은 번역 키다

라벨과 설명 칸에는 사람이 읽을 문장이 아니라 **번역 키**가 들어간다. 키는 `system_settings.` 뒤에
설정 키를 점까지 그대로 붙이고 `.label` 또는 `.description`으로 끝난다. 예를 들어 설정 키가
`security.ban.max_failed_attempts`이면 라벨은 `system_settings.security.ban.max_failed_attempts.label`이다.

문장 자체는 클라이언트의 번역 자원이 들고 있고, 클라이언트가 화면을 그릴 때 푼다. 그래서 언어를
하나 더 지원하는 일이 데이터베이스를 건드리지 않고 끝나고, 서버는 어떤 언어가 있는지 알지 않는다.
